# 大数据隐私保护实验冻结规范

> 冻结日期：2026-08-25  
> 当前阶段：UCI Online Retail 正式数据只读审计已完成  
> 范围限制：本阶段不实现 Laplace、GRR、Basic UE，不执行固定抽样，不生成 GT 或 MSE。

## 1. 正式数据

- 数据集：UCI **Online Retail** 一年版，数据集 ID 352。
- 官方页面：<https://archive.ics.uci.edu/dataset/352/online%2Bretail>
- DOI：`10.24432/C5BW33`；许可证：CC BY 4.0。
- 时间范围：2010-12-01 至 2011-12-09，全量使用，不按国家、月份或订单抽样。
- 原始文件：`data/raw/Online Retail.xlsx`，23,715,344 bytes，SHA-256 `43465a06f2ccf7c8b5bd2892bc7defb52f97487934fe93b16ae4c3936424676d`。
- 原始 Excel 与下载压缩包不提交 Git；来源、下载时间、大小和哈希记录在 `data/raw/source_metadata.json` 与审计结果中。

原始工作表 `Online Retail` 是“一行一个交易明细”，并不直接满足作业要求的“一行一个用户”。只有完成下述过滤、按客户聚合和篮内去重后，才得到用户级变长购物篮。

## 2. 冻结的数据转换规则

交易明细必须同时满足：

1. `CustomerID` 存在且可无损规范化为整数客户 ID；
2. `InvoiceNo` 去除首尾空白后不以大小写不敏感的 `C` 开头；
3. `Quantity > 0`；
4. `UnitPrice > 0`；
5. `StockCode` 去除首尾空白并转大写后匹配 `^\d{5}[A-Z]{0,2}$`。

唯一主排除原因使用上述固定优先级。独立规则命中数和唯一主原因计数均须保留，且“保留 + 各主原因”必须与全部原始明细对账。

过滤后，按 `CustomerID` 聚合全年全部保留明细，并在每名用户篮内对规范化 `StockCode` 去重。服务或调整代码仅通过严格格式规则排除，不采用人工黑名单或 `Description` 关键词。

## 3. 只读审计结果

权威机器可读结果为 `results/data/data_audit.json`，简明说明为 `results/data/data_audit.md`。当前已核验：

- 原始明细 541,909 条，完整重复明细 5,268 条；
- `CustomerID` 缺失或非整数 135,080 条；实际缺失值以审计结果为准，不沿用 UCI 页面概述；
- 唯一主原因：无效客户 135,080、取消发票 8,905、非正数量 0、非正单价 40、无效商品码 1,547；保留 396,337；
- 过滤前合法客户 4,372 名，过滤后非空客户篮 4,334 个，空篮 38 个；
- 过滤后商品 3,659 个；用户内去重移除 130,116 条重复用户—商品明细；
- 篮长最小值 1、中位数 35、95 分位数 204、最大值 1,785；所有篮均非空且篮内无重复商品；
- 原始纯数字 `StockCode` 最小值 10002，不从 1 开始且不连续。

合格 `StockCode` 后续按字典序稳定排序并映射为连续内部 ID `1..d`，同时保留正反向映射。本阶段只审计和预览映射规则，不生成映射文件。

## 4. 后续实验冻结口径

- 主实验在开始设计时先完成最小可行闭环，使用最简单的示例数据进行整个实验的验证。
- 主实验使用统一单商品统计目标：从每名用户去重后的非空购物篮中均匀抽取一个商品；抽样只执行一次并固定。
- Laplace、GRR 和 Basic UE 共享相同有效用户、商品域、固定单商品数据和 GT；不得把该 GT 与完整购物篮用户频数混为一谈。
- 增加/删除一名用户为邻接关系；每名用户贡献上限为 1，集中式频数向量查询的全局 `L1` 敏感度为 1。
- 隐私预算为 `epsilon in {0.1, 1, 2, 4}`。
- 每个“机制 × epsilon”配置独立重复 **200 次**。
- 根种子为 `20260825`；固定抽样流与 Laplace、GRR、Basic UE 的机制流相互隔离，机制流继续按 epsilon 和重复编号确定性派生。
- 每次同时保存原始浮点估计和逐坐标裁剪至 `[0,n]` 的估计，均不取整。
- **裁剪后 MSE 为主指标，原始（裁剪前）MSE 为补充指标**；报告均值、样本标准差及均值的 95% 置信区间。
